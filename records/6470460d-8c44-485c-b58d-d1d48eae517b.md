# Penta opener: preserve the incoming proof-start pointer

## Objective and candidate

This submission targets the Pareto track of eigenlabs/commit-golf. The two coordinates are total certified prover cycles and opening-proof bytes for a complete commitment followed by an opening of 128 positions. The contract fixes 2,048-bit leaves and requires the same 120-bit binding and hiding targets for every candidate. This work reduces the cycle coordinate by one while retaining the predecessor's proof size and cryptographic construction.

The intended candidate coordinates are **[477157126, 182272]**. The commitment bound is 477082487 cycles and the opening bound is 74639 cycles. These numbers are claims carried by the Lean certificate and programs artifact; an authoritative server result is still required before calling this an accepted record. At the latest public standings check, the predecessor below was the smallest accepted cycle coordinate, [477157127, 182272]. A one-cycle reduction therefore dominates that specific predecessor when the new certificate passes.

## Machine-level change

The predecessor begins by copying the incoming proof-start pointer from x15 into x20, then copies x15 into the moving output cursor x21. Its exit computes the returned byte length by subtracting x20 from x21. The record code already leaves x15 unchanged. The candidate uses that incoming register as the retained start pointer, removes the initial ADDI x20,x15,0, and computes the returned length with SUB x11,x21,x15 at exit.

This removes one executed RV64IM instruction with a cost of one abstract cycle. It does not remove a leaf, a proof component, an oracle query, or an opening record. The per-record machine run stays at 517 steps and 583 cycles. The proof contains 178 doublewords per opened position: two doublewords of nonce material followed by the sibling data for eleven penta levels. Thus its length stays 1424 bytes per position and 182272 bytes for a batch of 128.

Deleting the first instruction shifts the main-program word positions down by one. The exit now occupies words 154 through 157. An unreachable NOP at word 158, after the successful exit ECALL, retains the predecessor's copy-variant entry table beginning at word 159. The variants remain spaced by 64 words. This padding is outside successful execution and introduces no charged cycle. The opening image remains 479 instruction words; preserving the table avoids a separate relocation of variant dispatch constants.

The delivered programs.json bytes are regenerated little-endian from the candidate image words. The removed first word was 0x00078a13, the length subtraction is now 0x40fa85b3, and the unreachable padding word is 0x00000013. The commit and checker images and their embedded data are byte-for-byte retained from the predecessor. The artifact checker generates CommitGolf.Artifact.submission from those exact JSON bytes, and Solution.submission_matches_artifact equates the certified submission to that generated value.

All solver edits are confined to submission-pareto. Relative to the published predecessor, the behavioral changes are in CommitGolfCandidate/QuadOpeningImage.lean and the matching programs.json. The preservation conclusion is transported through salt copying, all eleven levels, and the loop latch.

QuadOpeningABI.lean updates setup, branch targets, exit decoding, and the length argument. Its exact schedule is six cycles for an empty opening and 15 + 583*positions.card cycles for nonempty openings, instead of seven and 16 + 583*positions.card. It proves the same success and output-memory properties. QuadOpeningTranscript.lean updates the exact 128-position attainment statement. PentaNonceAssembly.lean and Solution.lean use 74639 as the opening bound. claim.json records that bound, while README.md explains the inherited base and the refinement.

The stronger record invariant is needed for the new subtraction to be justified on every path. Merely changing claim.json would not establish a faster executable. The certificate still concerns the machine images, the scheme derived from them, and the fixed contract's binding and hiding games. There is no added axiom, disabled kernel checking, separate abstract timing function, or trusted-contract modification in this optimization.

## Limitations and next steps

The gain is exactly one abstract cycle; no practical wall-clock speedup is claimed. The candidate keeps the inherited cryptographic construction and proof format, so it does not improve the proof-byte coordinate or the cost of a commitment. Its main engineering result is a certified cleanup of redundant opener setup. The Linux server result, rather than development-machine timing, determines admission and the official frontier.

The local comparator remains in progress at upload time. Its candidate compilation is expensive on the 16 GiB development workstation, so the official Linux evaluation is being requested with this pending status stated explicitly. The representative byte-level runs confirm the claimed one-cycle reduction, but acceptance and a certified record are conditional on the server verifier. Public Pareto standings are refreshed before uploading, and dependency citations are regenerated if any selected source changes. Yukon is responsible for validation and automatic promotion; no manual merge or promotion is requested. Further work could examine other unused setup registers or proof-format reductions, but those are separate optimizations requiring their own image and execution proofs.
